# 协作感知

第三轮阶段 4。打开同一篇页面的其他成员会显示在标题下面。别人保存之后，当前页出现「有新版本」，可以先刷新再改，少碰到一次 409。这不是多人同时改同一段文字，也没有把两个人的输入合并。

## 做了什么

页面标题下方，在有其他人时显示一行头像。每个人是名字的首字，加上名字，以及「正在查看」或「正在编辑」。没有其他人时不留空行。自己的另一个标签页不会把自己算成另一个人。

别人把页面保存到更新的版本号之后，同一行下面出现「有新版本。刷新后再改，可以少碰到保存冲突。」点「刷新」会重新读取这一页，丢掉还没发出去的修改。如果本地还有未保存内容，提示里会加上「刷新会丢掉还没保存的修改。」刷新不会自动发生。冲突对话框已经打开时，不再叠这条提示，避免盖住原来的覆盖或放弃。

自己刚保存成功不会把自己的新版本当成别人的。比较的是「我已经确认过的版本号」和「轮询看到的版本号」，只有后者更大才提示。一次先发出去的轮询如果带回更旧的版本号，不会把已经出现的提示关掉，也不会凭空打开。

## 为什么用轮询

在线状态写在 `PagePresence` 表里。每个打开的页面大约每 5 秒发一次短请求，刚打开和点进标题或正文时会马上再发一次。请求体是 `viewing`、`editing` 或 `leave`。服务端记下这个人和时间，删掉超过 20 秒没心跳的行，再返回当前版本号和其他还在的人。

没有用服务器推送（SSE）或 WebSocket。取舍是：

- Serverless 函数有超时，也限制同时占住的连接数。一条 SSE 会把一次调用挂住，空闲几十秒就可能被平台切断。轮询每次马上返回，不占长连接。
- 多实例时，内存里的连接表只看得到连到这一台的人。数据库是各实例共用的，所以任意一台收到的心跳，其他台的下一次轮询都能看见。
- 代价是最多大约 5 秒才发现有人进来或有新版本，关掉标签后如果没发出离开请求，最多大约 20 秒还显示这个人。页面内跳到另一篇时不会立刻从旧页面消失，也是等到这 20 秒。
- 没有定时清理任务。任何人发心跳时，会顺手删掉全库里超过 20 秒的记录。一段时间内谁都没打开页面，过期行会留在表里，但读取时仍按 20 秒过滤，不会显示。
- 应用服务器之间的时钟如果差得比 20 秒还多，一个人可能被另一台提前看成离线。演示和常规部署里时钟差远小于这个窗口。
- 本地 SQLite 只有一个写入者。每个打开的页面每 5 秒多一次写，和自动保存抢同一把锁。人数一多会变慢。线上 PostgreSQL 没有这个限制。这是在线状态，不是把编辑内容做操作变换或 CRDT。

间隔是 `PRESENCE_POLL_MS`（5 秒），在线窗口是 `PRESENCE_TTL_MS`（20 秒）。满 20 秒整仍算在线，再久一毫秒就消失。

离开请求挂在 `pagehide` 上，并带 `keepalive`，关标签时尽量把人马上移走。组件卸载时不发离开，避免开发模式把刚写上的心跳立刻删掉。

## 谁能出现，谁能看到

心跳接口要登录，规则和 `canViewPage` 相同：

- 作者始终可以出现，也可以看到其他能看这篇页面的人。
- 公开可编辑的页面，工作区成员可以出现。正在改标题或正文时记成「正在编辑」。
- 公开只读的页面，成员可以出现，但只能是「正在查看」。就算客户端声称正在编辑，服务端也会改回查看。工作区所有者可以改正文，所以所有者可以是「正在编辑」。
- 私有页只有作者能看，也只有作者能出现。其他成员，包括工作区所有者，打开心跳接口会得到 403。
- 未登录的分享页不显示其他人，也不会替访客上报。`/share/[pageId]` 不使用编辑页，页面上没有头像，也没有「有新版本」。公开链接本身仍是只读。

只读成员也能看到「有新版本」并刷新。刷新是读取，不是修改。

## 表和部署

`schema.prisma` 增加 `PagePresence`：页面、用户、活动（`viewing` 或 `editing`）、最后心跳时间。同一页同一人只有一行。删除页面或用户时，这些行跟着删除。

`prisma db push` 会按当前模型建表。`scripts/apply-presence-migration.ts` 再用当前数据库的方言执行 `CREATE TABLE IF NOT EXISTS`。SQLite 用 `DATETIME`，PostgreSQL 用 `TIMESTAMP(3)`。表已经在时什么都不做。`npm run db:push`、`db:reset`、`db:deploy`、`setup` 和 `test:e2e` 都会在历史表脚本之后跑它。

`prisma/migrations/20261127140000_page_presence/migration.sql` 是 SQLite 写法。不要在 PostgreSQL 上执行这份文件，也不要改用 `prisma migrate deploy`。

重新播种时，两种数据库都会在删除页面和用户之前删掉 `PagePresence`。SQLite 原来的清空语句仍然逐条保留，测试里先滤掉这条新增的删除再比对。

## 如何验证

单元测试不连数据库：

```bash
npm test
```

只看这一阶段的页面：

```bash
npx playwright test e2e/presence.spec.ts
```

全量端到端会先推表、补历史表、补在线状态表，再播种：

```bash
npm run test:e2e
```

PostgreSQL 用同一条命令，把 `DATABASE_URL` 指到本机库，并设置 `DATABASE_PROVIDER=postgresql`。跑完后执行 `npx prisma generate`，把本地客户端换回 SQLite。

浏览器里用 `nash@folio.dev` 和 `mia@folio.dev` 登录，密码都是 `folio-demo`。Nash 新建一页并设成可编辑，Mia 打开同一地址。几秒内 Mia 能看到 Nash。Nash 再改标题，Mia 看到「有新版本」，点刷新后标题一致，接着 Mia 自己改标题可以保存，不会弹出冲突对话框。把页面改成只读后，Mia 点进标题，Nash 看到的仍是「正在查看」。未登录打开 `/share/页面id`，没有头像，也没有新版本提示。

## 发现的问题

自己的保存和一次已经发出的轮询可能交错。轮询先看到新版本号，保存响应还没把这个号记成「我的」。如果这时直接提示「有新版本」，作者会看到自己刚保存的内容。现在用两个数：自己确认过的版本号，以及轮询见过的最大版本号。只有后者更大才提示。保存成功时抬高自己确认过的号，不会把别人真正更新的版本号清掉。

同一账号的两个标签页不会互相显示头像。其中一个保存后，另一个仍可能出现「有新版本」。提示在标题下面，不挡住标题，也不会自动改掉正在写的字。原来的冲突用例继续自己保存并处理 409。

刷新会覆盖本地还没保存的修改。提示里写了这句话。正在保存时点刷新，会请用户等这一次保存结束。

分享页不报在线状态。一个只打开分享链接的人，编辑页里的成员看不到他。私有页上，工作区所有者也不会出现在作者之外。

关标签靠 `pagehide`。浏览器取消这个请求时，人会继续显示到 20 秒窗口结束。没有单独的后台清扫，所以这张表在完全没人使用时不会自己变空，只是不会被显示。

第一次推送的 SQLite 端到端里，只读用例等到 90 秒。Mia 点进只读标题时，焦点可能落在监听挂上之前，那一次心跳没有发出，后面的轮询又只记得上一次的状态，于是一直在等一条「正在编辑」的请求。现在每次轮询都重新看当前焦点，只读成员仍然会被服务端记成「正在查看」。关闭浏览器上下文时如果页面已经被超时拆掉，不再让清理步骤盖住原来的错误。
