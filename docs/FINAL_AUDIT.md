# 总体验收

验收命令：`npm test`，`npm run test:e2e`。端到端会 `prisma db push`、重新播种，再用 Playwright（Chromium，1 worker）打开 `http://127.0.0.1:3000`。大页面计时不在这套默认命令里。

本次验收结果：单元测试 **77 / 77**，端到端 **48 / 48**。阶段开始前的 29 个单元测试和 8 个端到端测试都还在，没有删除或放宽断言。

### 阶段 4 生产构建补测

同一套 `scripts/large-page.bench.ts`，服务器改为 `next build` 之后的 `next start`（`playwright.bench.prod.config.ts`）。320 个块的页面热刷新后，等到第 320 块可见；文档响应是 navigation 的 `responseEnd - requestStart`。

| 项目 | 第一次 | 第二次 |
| --- | --- | --- |
| 热刷新到第 320 块可见 | 130 ms | 165 ms |
| 文档响应 | 42 ms | 59 ms |
| domContentLoaded | 55 ms | 75 ms |
| load | 58 ms | 77 ms |

两次都在 200 ms 内看到全部 320 个块，文档响应不到 60 ms。生产模式没有再出现需要处理的加载问题，因此没有为这一项再改实现。开发模式里热刷新大约 1 秒、文档响应 539 ms，是开发服务器的开销。编辑侧的优化仍然有效：水合之后输入 137 ms → 16 ms，按键 286 ms → 25 ms，拖拽 1260 ms → 257 ms，长任务降到 0。明细在 [LARGE_PAGE_TEST.md](./LARGE_PAGE_TEST.md)。

### 阶段 5

**5.1 搜索。** `searchPages` 增加范围 `all` | `title` | `content`。`all` 保持原来的行为：标题命中就不再用正文重复记一条。`title` 不看正文。`content` 只看正文，标题里也有这个词的页面仍然会出现。接口是 `GET /api/workspaces/:id/search?q=&scope=`，非法的 `scope` 按 `all`。搜索框提供「全部 / 标题 / 正文」（`search-scope-all`、`search-scope-title`、`search-scope-content`）。每个大小写不敏感的命中都用 `search-highlight` 标出。私有页在进入搜索前就按 `canFindInSearch` 滤掉，非作者在三个范围里都看不到。

**5.2 权限。** 读和写跟 `canViewPage`：公开页对工作区成员可读写，私有页只有作者。删除和改可见性是所有者或作者。分享链接只对公开页（`canSharePage`）。非成员在可见性判断之前就被成员校验拒绝。矩阵测试 12 个，多于要求的 10 个，见下表。

**5.3 小屏和空状态。** 窄屏侧栏是抽屉，宽度 `min(272px, calc(100vw - 3rem))`，右侧留出页面。顶栏按钮 44×44。Esc 关闭抽屉。新建页面和切换工作区会先收起抽屉。小屏上页面行的加号直接可见，桌面端仍是悬停才出现。搜索框在小屏贴底。空工作区、找不到页面、无权访问、分享页缺失和工作区加载失败都走 `EmptyState`：图标、标题、`text-sm leading-6` 说明，需要时再给一个动作。加载骨架写明「正在打开工作区」或「正在打开页面」。搜索加载是「正在搜索…」。表单错误同样是 `text-sm leading-6 text-danger`。

## 剩余已知限制

- 没有实时协作。同一页在别处已经保存时，后提交停在冲突对话框上，要选择覆盖或放弃并刷新。
- 块内有加粗、斜体、删除线、行内代码和链接。斜体用倾斜变换，占位宽度和光标一致。链接只接受 http 和 https。
- 图片单张不超过 2MB，只接受 png、jpeg、gif、webp。
- 公开表示工作区成员可读写，外加一条不易猜到的只读链接，不是更细的权限表。
- 置顶跟页面走，收藏跟用户走。置顶页仍排在同级未置顶页前面。
- 数据库是 SQLite，适合单机演示，不适合多进程同时写。
- 开发模式下 320 块页面的热刷新大约 1 秒。生产构建两次实测是 130 ms 和 165 ms，文档响应 42 ms 和 59 ms，这项没有未处理的性能问题。
