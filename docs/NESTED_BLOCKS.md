# 嵌套块与层级拖拽

第三轮阶段 1。块不再只能挂在引用或折叠下面。任意块都可以成为父块。Tab 缩进，Shift+Tab 反缩进，拖拽可以放进另一块，也可以拉到另一层。不能把一块拖进自己或自己的子孙。

数据库里的 `Block.parentId` 原本就有，这一阶段没有加表，也没有迁移。

## 缩进

光标在普通块里按 Tab，当前块连同它的子树变成上一个同级块的最后一个子块。前面没有同级块时不动。Shift+Tab 把它升到父块的外面，紧挨在父块整棵子树之后。

反缩进时，原来排在它后面的同级块会变成它的子块，那些块自己的子树跟着走。例如：

```
父
  当前
  后面
    孙
```

对「当前」按 Shift+Tab 之后：

```
父
当前
  后面
    孙
```

这和大纲的层级一致：后面那些行本来就比父块更深，升上来的这一行接住它们。只拖拽时不会发生这件事，拖拽按落点放置。

代码块里的 Tab 仍是插入两个空格，避免打乱缩进。代码块改层级用拖拽。分割线可以 Tab / Shift+Tab。图片块的地址框继续用 Tab 在控件之间移动，改层级也用拖拽。

根块算第 1 层，最多 8 层。再缩进或拖进更深的位置会停住，并提示「块最多嵌套 8 层」。已经存进去的更深层级仍能读出来，只是编辑时不再往下加。

拖进折叠块时会把折叠打开，避免子块被收起藏住。

## 拖拽

握把仍是 `data-testid="block-drag"`。指针在目标块标题行（`block-shell`）上的位置决定落点：

| 位置 | 落点 | 结果 |
| --- | --- | --- |
| 上沿约 36% | `before` | 成为目标的前一个同级，层级跟目标一样 |
| 下沿约 36% | `after` | 成为目标的后一个同级，插在目标整棵子树之后 |
| 中间 | `inside` | 成为目标的最后一个子块 |

拖走的是整棵子树，子块不会留在原地。落在自己身上没有指示线。落进自己的子孙时指示线变红（`data-blocked="true"`），并提示「不能把块拖进自己的子块」，松手后树不变。

同级之间的上移、下移和原来的 before / after 拖拽仍然有效，现在也会带上子树。

## 保存、冲突、复制和 Markdown

`parentId` 跟块的正文、`marks` 一起交给原来的 `PATCH`。服务端仍用 `normalizeBlocks`。父块必须存在，并且不能指回自己或成环；不满足时清掉 `parentId`，文字留下来。引用和折叠不再是唯一合法的父块。

冲突还是按页面 `revision`。409 时后提交的人选择覆盖或放弃并刷新。两边的快照都包含层级，覆盖不会把另一边的 `parentId` 单独丢掉，放弃则整页回到服务器上的那一版。本地草稿在请求失败时不会被清掉，这一点和原来的自动保存一样。

复制一块时，选区里的子块会跟着走。贴进去的根块改挂到目标块的同一层，内部的父子关系保留，空块也保留。`marks` 和链接不因缩进或粘贴重排。

导出仍用 `:::child` … `:::` 包住子树，而且任何父块都可以，不限于引用和折叠。解析会数层级，所以子树里的折叠、图片和代码围栏不会把外层的 `:::` 提前吃掉。从 Markdown 回到块时，按顺序复用原来的块 id，并按这张对照表改写 `parentId`，避免子块指到已经被换掉的 id。

只读视图、分享页和 Markdown 预览用同一棵树渲染。折叠收起时子块不在页面上，数据还在。

## 发现的问题

拖到嵌套块上时，外层行如果因为内容没变就被跳过重绘，里面的指示线不会出现。现在只要落点在某块的子树里，那条祖先链都会重绘。

拖拽过程中如果提示条把正文往下顶，落点会从块的中部滑到边上。提示条改成不占高度，盖在编辑器右上角，避免把目标行挤走。

`docs/NEW_BLOCKS.md` 里「嵌套只允许挂在引用或折叠下面」是上一轮的限制，从这一阶段起不再成立。README 里「块只能在同级之间拖」也会在第三轮总审计时改掉。

## 还没做

- 代码块和图片块不能用 Tab 改层级，只能拖。
- 反缩进会收养后面的同级。只想升一层、不动后面的块，要用拖拽。
- 编辑时最多 8 层。
- 子树里的代码块如果某一行正好是 `:::` 或 `:::child`，Markdown 往返可能把围栏数错。正常代码围栏不受影响。
- 没有实时协作。两个人同时改层级，仍然走原来的 409 冲突。
